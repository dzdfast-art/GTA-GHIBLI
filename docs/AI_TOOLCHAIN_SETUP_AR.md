# تجهيز أدوات فحص GTA GHIBLI (Godot 4.7)

هذه الإضافة التحضيرية لا تغيّر ملفات اللعب أو المشاهد أو الأصول. أُنشئت على فرع مستقل حتى تبقى `main` كما هي.

## الأدوات الثلاث

### 1) Godot Editor MCP — ربط مساعد التطوير بمحرر Godot

المصدر: https://github.com/hybridindie/godot-mcp

هذه الأداة تتكوّن من جزأين: إضافة داخل مشروع Godot، وخادم MCP يعمل على الكمبيوتر الذي يشغّل Godot. لذلك لا يكفي رفع ملفات إلى GitHub لتشغيل الاتصال؛ يجب تثبيت الخادم على الكمبيوتر نفسه.

**على كمبيوتر Windows / macOS / Linux:**

1. هذا الربط يحتاج **كمبيوتراً يعمل بنظام Windows أو macOS أو Linux**؛ لا يمكن تشغيل خادم Godot MCP على هاتف Android وحده. يلزم Godot 4.7 وPython 3.11 أو أحدث.
2. نزّل مستودع الأداة من https://github.com/hybridindie/godot-mcp (زر Code ثم Download ZIP) وفك ضغطه على الكمبيوتر.
3. ثبّت مدير الحزم `uv` من https://docs.astral.sh/uv/getting-started/installation/ ثم افتح الطرفية داخل مجلد `godot-mcp` الذي فككته.
4. شغّل `uv sync`، ثم تحقق بالأمر `uv run godot-mcp --help`.
5. انسخ المجلد `godot/addons/godot_mcp` من مستودع الأداة إلى مجلد مشروع GTA GHIBLI بحيث يصبح المسار `GTA-GHIBLI/addons/godot_mcp`.
6. افتح مشروع GTA GHIBLI في Godot، ثم اذهب إلى Project → Project Settings → Plugins وفعّل `godot_mcp`.
7. شغّل الخادم من مجلد مستودع الأداة بالأمر `uv run godot-mcp`. افتح بعد ذلك عميل MCP محلياً مثل OpenCode واضبطه على تشغيل الأمر نفسه من مجلد الأداة.

**مهم جداً:** هذا لا يضيف زر اتصال تلقائياً داخل محادثة ChatGPT على الهاتف. خادم Godot MCP يتطلب برنامجاً آخر يعمل كعميل MCP محلياً؛ مستودع الأداة يوثق OpenCode وClaude Code. لا تضع أسراراً أو مفاتيح وصول في GitHub. اترك الاتصال محلياً، وابدأ بأدوات `inspection` للقراءة فقط. أدوات تعديل المشاهد والملفات والتشغيل والتصدير متوقفة افتراضياً ويجب تفعيلها فقط بعد مراجعة صلاحياتها.

الشرح الرسمي وطريقة الربط: https://github.com/hybridindie/godot-mcp

### 2) GdUnit4 — اختبارات تلقائية داخل Godot

المصدر: https://github.com/godot-gdunit-labs/gdUnit4

1. افتح مشروع GTA GHIBLI في Godot 4.7.
2. افتح تبويب AssetLib.
3. ابحث عن GdUnit4.
4. اختر الإصدار المستقر GdUnit4 v6.2.3؛ صفحة المشروع تسجل توافق سلسلة 6.2.x مع Godot 4.7.
5. افتح Project → Project Settings → Plugins.
6. فعّل GdUnit4 ثم أعد تشغيل المحرر إن لزم.

بعد التثبيت، تُنشأ اختبارات منفصلة في مجلد `tests/`. لا تُعدّ الأداة مثبتة أو ناجحة حتى يظهر GdUnit4 Inspector وتُشغّل اختبارات فعلية. لا توجد اختبارات لعب مضافة تلقائياً في هذه الخطوة.

دليل التثبيت: https://godot-gdunit-labs.github.io/gdUnit4/latest/first_steps/install/

### 3) GDScript Toolkit (gdtoolkit) — فحص أسلوب وجودة السكربتات

المصدر: https://github.com/Scony/godot-gdscript-toolkit

تُشغّل هذه الأداة آلياً في GitHub Actions بواسطة الملف:
`.github/workflows/gdscript-lint.yml`

وهي تفحص تنسيق وقواعد كتابة GDScript. لا تثبت وحدها أن منطق اللعبة صحيح، ولا تستبدل تشغيل Godot أو اختبارات GdUnit4.

أوامر التشغيل المحلي بعد تثبيت Python:
```bash
python -m pip install --user gdtoolkit
gdlint scripts
```

## ماذا أُضيف إلى المستودع؟

- سير عمل GitHub Actions لتشغيل gdlint على ملفات GDScript التي تغيّرت في كل دفعة أو طلب دمج.
- هذا الدليل العربي لتثبيت الأدوات الثلاث والتحقق منها.
- أظهر أول تشغيل شامل 348 ملاحظة أسلوبية موجودة مسبقاً في الملفات: 297 لطول السطر، و34 لعدد return، والباقي لترتيب التعريفات وأسماء preload والوسائط غير المستعملة والمسافات النهائية. هذه ملاحظات أسلوبية وليست 348 عطلاً مؤكداً في اللعبة أو أخطاء ترجمة.
- لتجنب إيقاف كل تغيير جديد بسبب هذا الرصيد القديم، يفحص GitHub Actions الملفات `.gd` المعدلة فقط. أما فحص المشروع كاملاً فيبقى عملاً منفصلاً لتقليل الملاحظات تدريجياً.

## ما الذي لم يحدث بعد؟

- لم يتم تثبيت أي برنامج على هاتفك أو حاسوبك.
- لم يُنشأ اتصال MCP داخل ChatGPT؛ دليل Godot MCP الحالي يصف عميل MCP محلياً مثل OpenCode أو Claude Code.
- لم يتم إدخال إضافة MCP إلى ملفات المشروع من هذه الخطوة؛ لأنها تحتاج إلى تنزيل إصدارها المطابق وفكّه داخل نسخة المشروع المحلية.
- لم يتم تثبيت GdUnit4 داخل المشروع بعد.
- لم يتم إجراء أي تعديل على مشاهد اللعبة أو السكربتات أو الأصول.
- لا يعني نجاح فحص lint أن اللعبة تعمل أو أن APK صالح.

## طريقة المراجعة الآمنة

1. راجع هذا الفرع والملفات المضافة.
2. راجع نتيجة GitHub Actions.
3. ثبّت الإضافات محلياً بعد أخذ نسخة احتياطية.
4. شغّل الاختبارات وسجّل النتائج.
5. لا تدمج الفرع إلى main قبل مراجعة نتائج الفحص والموافقة.
